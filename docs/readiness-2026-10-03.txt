Corrections
- Repeating an identical Hearth assignment no longer resets work or deposits a
  carried load instantly. A different job (including rest) finishes carrying the
  existing load home before beginning the new job.
- Payments accepted within the existing floating-point tolerance clamp their
  final balance to zero, so ordinary arithmetic cannot produce a negative stock
  that the save validator subsequently rejects.
- Cave saves with contradictory completion/event flags are rejected before they
  can strand the fire sequence. Valid v1 saves remain unchanged. There is no
  documented pre-v1 migration; unsupported versions are rejected, not guessed.
- Hearth export after a failed write exports current progress, not an older
  stored snapshot. A save rejected at load is retained verbatim for recovery.
- Builds decode file URLs correctly in checkout paths containing spaces or '#'.
