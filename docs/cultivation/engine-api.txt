quoteAdoption(rawV6) -> {ok:boolean, reason:string|null, requirements:[string],
  sourceVersion:6|null, sites:[{id,x,y,width,height}], profile:profiles}
Pure. Accept an exact JSON string that the preserved validator accepts as v6,
with opening checkpoint actually satisfied and new authored sites accessible/
unobstructed. Reject unsupported/damaged content without changing it. Adoption
does not require every old actor/job to settle. This does not itself activate
support or issue stored seed/water. No mutation or storage inside this API.

adopt(rawV6) -> Camp; throws Error with quoteAdoption.reason if unsupported.
Returns an isolated copied v7 state with old IDs/positions/paths/orders/work/
custody unchanged. Source water pool30, seed cache6 and new plot geometry are
the declared new authored source profile. Exact original raw bytes remain the
root-owned envelope archive; root commits archive + candidate in one value
before publishing returned Camp. No writes occur in adopt.

new Camp(state) -> validated isolated v7 Camp; throws if invalid/unknown tuple.
valid(state) -> boolean, total nonthrowing predicate. Own closed v7 validator,
not a fabricated/refunded v6 projection. `camp.s` is the authoritative state;
serialize() returns its JSON string, not a persistence envelope. BigInt is used
only inside arithmetic; wire values are canonical bounded decimal strings.
The root-owned envelope carries exact sourceRaw alongside this state; envelope
validation validates source separately and does not re-run adoption on reload.

Plot IDs are `pilot`, `woodland`. Collection targets are those plot IDs plus
`water` and `seed`. collect('water',ids) is standing bare source collection;
collect('seed',ids) requires pilot inspection discovery and finite cache source.
collect(plotId,ids) assigns output hauling; woodland harvest uses resume(),
whose quoted/visible action is `Harvest woodland` in that phase. Output collection
has seed-first pickup; the order repeats until the current tray is emptied.
An exhausted source/empty tray is a rejected command or a truthful idle state.
New work commands retain old loaded-work-switch return-first semantics. Explicit
Move with cargo and Stop/Return preserve each new custody tag.
cancel(id) retains old building behavior; callers use cancelPlot for the new job
to avoid ambiguous IDs. Started jobs cannot material-refund; stopping actors is
ordinary command(ids,{kind:'idle'}). cancelPlot releases only unstarted owned
obligations through actual recovery, never teleports carried/staged inputs.
All failed new commands are atomic and have no actor/material/progress mutation.

Integration boundary
Root owns Web Lock, envelope parsing/version/size caps, exact source archive,
save/import transactional publication, visibility/pause scheduler and displayed
formatting. Engine advances only on tick(.1); no timers/DOM/storage/network.
No tick when paused/hidden/unowned. Adoption preview and inspector queries
advance nothing. Root should persist discoverPlot as a command because it marks
the cache discovered; that action changes information only, never material.

Frozen numeric refinements
quotePlant.action is exactly "Plant protected recovery crop" when NEXT may fund
the current pilot without its replacement. plant promotes that certificate
atomically, sets nextFunded=false and protects remaining ACTIVE work. Optional
tool-assisted extraction falls back to bare until NEXT is restored; new Tools,
construction and woodland spending wait. Existing paid old jobs can settle or
pause safely and are prospectively charged; no retroactive finish guarantee.
summary includes nextFunded, nextMissing and supportReason. protected amounts
are support-only third-milli; protected.nextRecipeWater is3 when NEXT funded
and0 otherwise. All actual recipe source reservations remain in job.sources.
inspectPlot action for cancelling is "Recover planting supplies"; resume accepts
that phase to assign new recovery workers after Stop/reassignment.
New wire layout is authoritative in the three owned source modules. Browser
load order: preserved HearthRTS -> CultivationLedger -> CultivationJobs ->
HearthCultivation. No old engine/profile is reinterpreted as cultivation.
