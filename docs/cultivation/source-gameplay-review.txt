REQUIRED CORRECTIONS

F1 — Cancelled plot supplies lack a UI recovery action after interruption.
Observed view.js303–306 enables plot-resume only for supplying/planting/harvest.
jobs.js26 supports resume for cancelling too, and jobs.js30/43 implements staged
supply recovery. Concrete path: reserve a crop, deliver some inputs but do not
begin planting, cancel, then Stop/reassign every recovery worker. The paid job
remains cancelling with staged seed/water. The visible Resume button is disabled;
Collect requires output; right-click a plot inspects it; Gather->plot calls Collect
and rejects it. The player cannot assign another villager to perform the existing
safe recovery operation. This can strand the bed and its seed until an out-of-UI
action, despite the engine already having the necessary recovery command.
Minimal correction: enable the existing resume operation for cancelling with the
label "Recover planting supplies"; show staged/carried goods and the remaining
recovery action. Preserve input/cargo and invalid-order semantics.
Spark regression: cancel with staged supplies, Stop all involved workers, choose
a different worker through actual controls, recover every staged load, reload
mid-recovery, then show a new valid paid crop can begin with no duplicate seed.

F2 — New decision paragraphs inherit light-on-light styling.
styles.css sets #cultivation-panel background #dcd4b7 and panel color #263b30, but
aside p already sets its own color #aab9a9. The panel paragraph rule does not
override that explicit child color. #plot-quote/#support-status use the still
lighter #e9e2c9 background with the same light paragraph text. Thus the exact
support, shortage and recovery information is configured with very low contrast.
This is a source-level readability defect, not a claim of viewed browser pixels.
Set an explicit dark color for these paragraphs/statuses and inspect actual
Spark PNGs. Also #recruitment-note uses #4d5b3b on the dark outer page; retain a
legible muted-light color there rather than treating it as part of the light card.

F3 — Missing resources are exposed in internal units, not player quantities.
view.js259 directly formats q.missing.amount, resource, unit and location.
ledger.quoteProvision/jobs.missing expose amounts in third-milli and location b0.
For example9000 third-milli of water means3 water, not9000 collectible units.
The current public quote would say internal large integers and "at b0" during the
most important blocked decision. Convert them for display with a declared rounded
precision and real store name; keep the exact values in the engine/evidence.
Do not combine the whole-recipe shortage and support shortage so the same missing
material is counted twice. Where whole-item collection must round up, say how
many whole items to bring rather than implying a fractional physical item exists.

F4 — Protected-water wording understates recipe obligations; NEXT shortage
     disappears while a paid pilot batch owns the bed.
jobs.summary currently returns protected from L.holds(), which covers support
allowances only. NEXT's3 whole recipe water is separately subtracted in L.balance.
view.js292 labels that support-only number "Protected support and recipe
allowance", so a single NEXT can display0.3 water although3 additional whole
recipe water are protected. Keep recipe water and support allowance explicit.
For a normal first pilot, show the current and next crop obligation separately;
the visible single-batch recipe/support line must not conceal the initial second
reservation behind a generic note.

summary also exposes nextMissing, but cultivationUI never renders it. After Plant
protected recovery crop promotes NEXT to ACTIVE, a growing/planting/output pilot
can coexist with NEXT unfunded. quotePlant exits early because the bed owns a job,
so its quote contains no missing vector either. The user sees only "Restore ...
with ordinary gathering or committed output", not the required quantities.
Render the unfunded NEXT vector independently of the selected bed's phase, name
the Hearth supplying store and give the real collection/transfer remedy. An
empty/paid bed should not hide the binding funding constraint.

F5 — Successful sidebar orders leave an earlier armed map command live.
view.js327/329–331 call applyCultivation directly; applyCultivation commits and
renders without clearing mode/placement. For example arm Move, then click Collect
water: the villagers receive collection, but the tray still says Move and the
next map tap can issue the earlier move instead of inspecting. dispatch's success
path clears the command, but these newly added explicit actions do not.
Clear arming/placement after a successful explicit new order. Preserve the armed
state and previous orders for failed admission if that is the accepted contract.
Inspection actions should remain neutral; clearCommand/cancelInput must not Stop
the villagers. Include keyboard/touch cases in actual-control evidence.

PRODUCT CLARITY CORRECTIONS / REQUIRED VISUAL CHECKS

P1 — Narrow layout gives the whole new decision panel half a row.
At max720px aside becomes a two-column grid; only .mission is full-span. There
is no full-span rule for #cultivation-panel. At390px this places the new quotes,
phase text, two-column actions and support details into roughly175px before
panel padding. This is a predictable cramped layout risk even after contrast is
fixed. Use a full-width cultivation panel at the narrow breakpoint, then inspect
actual390x844 viewport PNGs for quote, recovery action and tray clearance. No
static CSS review can certify the eventual full-page/viewport geometry.

P2 — Inherited tools are described as an unconditional active speed.
workshopUI retains "Toolset complete ·0.60→0.45 seconds per item" and the old
unqualified extraction-benefit paragraph after adoption. In the new profile
funding can fall back to.60 without losing the tool entitlement. Qualify the
inspector as funded tool pace and state retained ownership/bare recovery plainly.
The engine extraction branch does retain tools and switches intervals; this
finding concerns the visible current meaning of the old benefit.

P3 — Primary opportunity is static once support starts.
nextOpportunity always promotes generic pilot/growth advice after activation,
regardless of mature output, woodland harvest, interrupted cancellation or an
unfunded NEXT. The lower panel has more detail, but the primary next-action
shortcut does not follow the real constraint. Keep one actionable promotion:
recover supplies, collect ready output, harvest woodland, resume funded work,
or inspect the missing NEXT vector as applicable. Growing guidance is appropriate
while growth actually runs; do not create a compulsory objective counter or an
automatic new job to make this dynamic.
