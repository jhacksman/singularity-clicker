Why the cause is removed

The old source put the full state/load text in a single small element, constrained beside a floated portrait and forced to nowrap/hidden/ellipsis. At390px the selected card could be about79px wide and visibly showed only "Holding…".

The appended rule uses .unit-card[aria-pressed=true] within @media(max-width:720px). Its specificity exceeds the base .unit-card and .unit-card small selectors, and it comes after the existing mobile rules. flex-basis140px and min-width140px, together with existing max-width140px and border-box sizing, fix a selected card's outer width at140px. The status remains display:block through the existing button-small rule, but clear:both places it below the portrait. white-space:normal and overflow-wrap:anywhere allow its complete existing state/load string to wrap, while overflow:visible and text-overflow:clip remove the ellipsis/clipping mechanism. Neither card nor roster has a fixed maximum height or a clipping overflow rule; the card can grow with wrapped text. Existing44px minimum touch height is retained.

Selection and multiple selection

view.js:273 sets aria-pressed from selected.has(u.id) on every UI refresh. The rule therefore follows actual selection rather than only the inspected unit or idle phase. Tapping a different card restores the old card's compact presentation and expands the newly selected one. Shift selection, Select all at line270, and Idle selection at line167 can mark several cards true; each receives the full rule. The CSS does not create a first-selected-only assumption or alter any event handlers, focus attributes, unit status strings, engine state, or command targeting.

The existing roster uses flex-wrap:wrap. At390px the normal roster content width is approximately340px after the main gutters, roster borders, and padding. Two140px selected cards plus an8px gap fit; three do not. Mixed selected/unselected rosters can redistribute cards and create additional rows. That is an intended layout consequence, not evidence of changed selection identity. The existing stable card elements and click handler do not replace controls merely because their size changes.

Eight-unit boundary

The engine admits at most eight units and training stops at eight. With all eight selected at390px, the width rule implies four card rows; the roster grows in normal document flow. There is no static clipping box that would truncate those rows. Additional rows can extend beneath the initial viewport or the fixed tray, so source inspection cannot establish that every card is simultaneously visible or tappable without scrolling. The below520px body padding remains290px and the tray remains fixed; those facts support a scroll recovery route but are not a measurement of occlusion or hit testing. The separate gate should verify each selected card can be brought above the tray and tapped, without demanding all eight fit at once.

Desktop and width boundary

The new rule is inactive above720 CSS pixels. Desktop source styling, command-tray styling, and engine behavior are unchanged. At exactly720 it applies; at721 it does not.
