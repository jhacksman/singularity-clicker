Rendering oracle

Each selected name/status string is checked against an actual Journey download
of the current live world and the real Pause/Resume control. Per-character DOM
Range rectangles then check the complete rendered name and status against card
bounds, clipping ancestors, viewport, portrait overlap, neighboring cards, and
fixed command-tray occlusion. elementFromPoint samples verify the glyph centers
belong to the selected card. The page must not overflow horizontally. Move and
Stop must have visible viewport-contained, hit-testable, enabled44px targets.
These assertions check outcomes; they do not require the particular flex-basis,
clear, wrapping, or overflow declarations chosen by the product owner.

All captures use fullPage:false. Every PNG has a geometry JSON containing
viewport, scroll, selected actor state, running flag, per-character rectangles,
computed font sizes/line height/overflow, all card rectangles, tray position,
control hit results and issues. Independent raster inspection remains necessary:
automated rectangles do not establish typography quality or player comprehension.

Real inputs, clocks and export synchronization

The harness uses Playwright touchscreen taps on visible selected cards, Move,
Stop and the visible map point. It verifies armed Move and records trusted touch
pointerdown events for all required targets. It does not dispatch fabricated
pointer events or call hidden view/reducer functions to issue browser commands.
Desktop uses actual mouse selection. The recorded scrolling is test-driven
ordinary window scrolling, not a claim of an observed physical swipe.

The seeded game starts paused. A Playwright clock is explicitly installed and
frozen; simulation advances only with declared runFor intervals. The Moving case
actually resumes the game, advances time and actor position, and captures with
Pause still displayed. The Journey dialog temporarily prevents advancement but
does not toggle the underlying paused flag; it is closed before measuring and
capturing the selected card. The shared oracle derives Moving versus Move planned
from exported phase plus the real current pause control, and exact expected text
must agree. It cannot rename a paused planned checkpoint as Moving.

Journey downloads install their download promise before the actual Export tap,
save/read the resulting file, and close the dialog. Each render/scroll/capture is
bracketed by exact live exports under the frozen clock. Selection-only changes
also preserve exact raw bytes. Move/arrival/Stop preserve every actor's load and
resource; material totals stay equal, and stock/spent/delivered/deposits remain
unchanged by the bounded Move/Stop sequence. Stop is only tested through accepted
return planning with its cargo retained; this harness does not duplicate delivery
settlement/custody mechanics already attributed to Move025.

Scaling is a labeled test-only CSSOM fixture that doubles measured computed px
font sizes for roster names/statuses. It adds no markup and does not change game
state. Portraits, controls and the rest of the page are not enlarged. It is not
browser zoom, whole-page text resizing, assistive technology or physical-device
accessibility evidence. No arbitrary timeout sleeps are used.

Artifacts, failure behavior and remaining gates

Spark writes artifacts/hearth-rts-touch-status with source/fixture hashes,
viewport PNGs, glyph/geometry JSON, original live export files, trusted input
telemetry, videos, and report.json. A browser-stage failure writes a viewport
failure PNG plus failure.json with available body/scroll/events and prior report
observations. Early fixture/build-identity assertions fail before browser capture
and are attributable through the Spark process log.
