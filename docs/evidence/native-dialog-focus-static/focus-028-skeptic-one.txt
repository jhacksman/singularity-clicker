Primary-source context, consulted read-only

The HTML Standard's sequential-navigation algorithm allows transfer to browser
controls at a document boundary; it does not promise an immediate wrap from the
last dialog button to its first button. Its modal inertness rule excludes the
modal element and its descendants from the otherwise inert document. These support
retaining strict background-focus rejection without treating the modal root as
background leakage. They do not prove what Chromium's next Tab will do here.
[HTML sequential focus navigation](https://html.spec.whatwg.org/multipage/interaction.html#sequential-focus-navigation)
[Modal dialogs and inert subtrees](https://html.spec.whatwg.org/multipage/interaction.html#modal-dialogs-and-inert-subtrees)

The dialog focusing model explicitly recognizes the dialog itself as a possible
focus target. That concerns the standard's dialog model, not a normative proof
that this exact observed re-entry order is mandated or universally desirable.
[Dialog focusing steps](https://html.spec.whatwg.org/multipage/interactive-elements.html#dialog-focusing-steps)
