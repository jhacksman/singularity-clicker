Supplementary negative-control runner
The final QA-only change preserves all tested assertions. It adds a C01 rejection
marker and passes field/state into each existing isolated C02 child so its failed
admission assertion names source versus pickup. The runner hashes and requires
the exact vulnerable00166e engine, copies the candidate test bytes unchanged into
a private mkdtemp tree, and substitutes only the engine there. Exact anchored
test-name filters run C01 and C02 separately with a240-second timeout and8MiB
output bound. Success requires normal exit1, no signal/spawn error, the named
test, its specific assertion marker and a TAP not-ok record. A no-match exit0,
generic setup failure, timeout or parse failure without that named assertion
does not satisfy these conditions. Full logs/hashes and failure details are saved
before the runner fails. The owned temporary tree is removed in finally; the
candidate source is never a cleanup target and is compared byte-for-byte after
both controls. Output consists of test diagnostics and local test paths, with no
secret read or network output path in this script.

Its C02 negative run intentionally stops at the first failing source-array
assertion. It does not establish separate negative sensitivity for inherited
keys or planned-pickup IDs; the corrected-engine test still loops over those.
The runner explicitly limits its evidence to reducer regression failures, not
an observed browser adoption/save/refresh chain. No negative run was executed
here. Runtime command compatibility and actual marker-bearing failures remain
Spark checks.
