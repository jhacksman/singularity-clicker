Ledger
construction.sites contains at most the actual unfinished physical sites.
Each site has buildingId,state(active/cancelling),sources(current unpicked
resource amounts keyed by actual store),staged vector,released vector,returned
vector, and bounded delivered-origin snapshots in origins. Its recipe is the canonical
building kind/cost, not caller-provided material amounts. Origin snapshots name
source store id/kind/x/y/resource/amount; they survive retirement of that store.
Active invariant per resource: sources+staged+taggedcargo=recipe; released and
returned are zero. Cancelling invariant: staged+taggedcargo+released+returned=
recipe, sources empty. Reserved goods stay in actual source inventory and do
not enter spent. Available stock subtracts construction sources AND transfer
reservations. staged is separately owned onsite WIP, not spendable storage.
Global fixed inventory is wild+all actualstores+all cargo+all staged+spent.
Spent excludes new unfinished sites; it receives exactly the complete bill when
the funded site completes installation. Old prepaid sites remain spent as before.
New outpost reclaim claim issues only at completion, backed by delivered origin
snapshots. It must not dereference a historical source as a current usable store.
No double authority with transfer/reclaim cargo or old paid reservations.

Finite autonomous supply/work
The existing Build-site order means fetch remaining material, deliver, then
install. One assignment repeats the16outpost or14workshop five-item loads with
all selected workers; no per-load confirmation. Empty-handed assigned workers
choose reachable pending source/type deterministically. At an actual source
edge, atomically decrement store and that source reservation by min5 remaining,
set named site cargo, and start a real source-to-site path. Other workers cannot
take the same last material. Pickup has no installation/work/stock grant.
Tagged cargo has site identity and its actual source snapshot. At an actual
site edge, unload into staged and add delivered-origin quantities; cargo clears.
No usable store/drop-off exists until all inputs are delivered AND the original
24/32 worker-seconds complete. Empty workers waiting at site retain Build-site
order and resume without extra clicks as deliveries arrive. Idle/funded waiting
is status; no invented urgency/upkeep.

Manual override/custody
Loaded Move starts immediately with the same construction cargo and holds it
on arrival. It pauses that worker's automatic site delivery. Stop/other work
physically return that cargo to a reachable real store under existing disclosed
return-first semantics. If the site remains active, receipt re-reserves exactly
that returned load at the receiving store for the same site; it never becomes
unfunded or counts as gathering/transfer/reclaim. A later Build-site assignment
can fetch it. If site is cancelling, receipt frees the goods and records that
site's returned quantity. Non-site orders retain manual authority; no automatic
site controller steals the worker back. Repeated/invalid commands preserve the
whole accepted state. New placement replans actual site-delivery intent rather
than routing every loaded worker home.

Cancellation
Active Cancel immediately releases only unpicked source reservations into free
stock, with no stock addition; stores already own them. It changes the site to
cancelling and stops future build work. Onsite WIP and carried quantities retain
physical custody. Site-assigned carriers return their present load; empty site-
assigned workers recover staged materials in ordinary five-item trips. Manual
Move/held site cargo retains manual control and offers Stop and Return. Existing
Build-site action on the cancelling site means Resume supply recovery, with
explicit label. Recovery requires a reachable store; blocked cargo stays held.
Remove footprint only after all remaining onsite/cargo/queued/live references
settle. With no picked material, cancellation can remove the empty footprint
immediately. Repeated Cancel never refunds twice. Completed outpost continues
current reclaim; completed workshop reclaim is still outside this slice.

Cancellation order table (explicit inherited semantics)
* If next is Build(cancelledSite), replace next with Idle, rather than null:
  finish the current physical return and then idle. Never revive the Gather,
  Build(otherSite) or other old order which the player had already superseded.
  Ordinary gathered/transfer/reclaim cargo keeps its existing receipt authority.
* If next names another manual order, preserve it exactly. Site cargo returns
  physically once, then the unrelated successor starts. Cancellation may not
  replace that successor with recovery of the cancelled site.
* Only a current Build(cancelledSite) with no queued successor is the site's
  active autonomous assignment. Its loaded worker returns; its empty worker
  may recover onsite supplies. Current Move/held/Idle manual intent is retained.
* Final settlement clears only obsolete references to the removed site, leaving
  other current/queued orders and their custody untouched.

Current pickup allocations and delivered origins are different records. A load
picked atA, returned toB and then fetched fromB records B when actually delivered
to the site. An old delivered-origin snapshot never reserves A again. Origin
rows sum to the current staged vector; cancellation pickup reduces those rows
with the staged material. Recovered site loads use a recovery tag, not a forged
new source-store purchase. Original quote history is not a material authority.
