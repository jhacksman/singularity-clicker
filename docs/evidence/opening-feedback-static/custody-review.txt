Initial disposition: HOLD for two concrete feedback regressions.

F1 — First-item partial work misattributed to Tools (fixed in current source).
Original feedback.js seeded load provenance at cargo 0 -> 1. A gatherer can have
cargo=0 and work>0 while tools=false; another worker finishes Tools before that
first item is credited. The first credit then sees tools=true at both tick ends,
so the original observer marked the entire subsequent receipt producedWithTools.
The same false inference occurred when a new session began partway through a
first item's work. This violates the promised entirely observed post-Tools load.
The unchanged engine accumulates extraction work before testing its interval and
does not discard existing gathering work when Tools completes (engine.js:460-461).
Smallest fix: seed from an observed empty load with zero first-item work before
extraction, retain provenance across every observed tick and taint on Tools change.
Root implemented that condition and removed first-credit seeding. Static re-review
of feedback.js SHA256 c06cdff73acd6151c8e548ef368fd4d2064f3aa715b6e5a9b9b49ba8bf332c82
accepts this fix. QA owner was asked for real-engine negative witnesses covering
partial first-item work and a mid-item imported/new observer, in addition to the
already present older carried-load test.

F2 — Narrow layouts hide the retained history after acknowledgments expire.
The preexisting <=720px CSS sets #log {display:none}. New toast expiration after
seven seconds therefore removes the last command acknowledgment from narrow/touch
UI entirely, while the newly added RECENT COMMANDS label remains visible without
content. This conflicts with retained visible historical commands in the spec.
Smallest fix: make the history visible on narrow layouts and group label/content
into one coherent responsive grid child. Root was notified. Re-review pending.
