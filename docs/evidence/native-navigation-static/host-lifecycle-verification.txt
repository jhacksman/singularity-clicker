helper clears the host reference before calling the previous controller's dispose
(:128). The widget then removes its click/storage listeners, marks itself disposed
and invalidates its pending generation. Its rendered DOM can survive a cached
document restoration, which was the original plan omission.

view.js:155 now handles pageshow only when event.persisted is true, resets lastNow
to current performance time, and calls mountNavigation. The common mount helper
requires modal.open and the native #campaign-navigation slot (:129-130). It first
disposes any previous reference and synchronously assigns the newly returned
controller (:131-135). Its initial refresh performs fresh source inspection.
There is no save(), action activation, location change or automatic game entry in
this handler or mount helper. This gives the restored controls a live listener
without reusing the disposed controller or its stale snapshot.

The guard also handles the necessary negative cases: a closed completion dialog
does not remount; another modal without this slot does not remount; ordinary
non-persisted page load does not auto-open or mount a completion panel. The only
slot in this host source is created by completion() inside modal-content. Repeated
restoration/remount calls replace the old controller instead of stacking listeners.
The existing dialogPauses state remains true for the still-open cached modal,
and resetting lastNow avoids treating the time away as an active Cave interval.

Controller ownership, close and replacement

The mount return is assigned synchronously, without awaiting ready. In the widget,
ready is an asynchronous refresh promise and mount returns the controller directly.
Thus Close/Stay/Replay/another modal can dispose it even while initial source
reads/digests are outstanding. The widget's disposed/generation checks prevent
the old refresh from rendering, an activation awaiting refresh from navigating,
and a rejected old callback from replacing a new controller's status.

openModal() disposes before replacing modal-content.innerHTML (:137). Help,
Settings, reset/import confirmation, prestige, load recovery and the existing
storage-conflict dialog therefore inherit cleanup. closeModal() disposes before
native dialog.close() and preserves the prior pause/time/render restoration (:138).
Stay retains that same close function, while Replay retains its existing replay,
save and close sequence (:152). Intentional Replay is not a widget-side save.

Native Escape cancel now prevents its default and calls closeModal explicitly
(:139). Direct native close is covered by the close event. Crucially, that handler
does cleanup only when !modal.open. A close event queued before a synchronous
reopen cannot dispose the newly mounted panel or mark its live modal unpaused.
If the modal remains closed, duplicate cleanup is safe because the host reference
was already null. Existing backdrop hit testing still calls closeModal.

I tried to find a path in this patch that renders a replacement modal while
retaining its old navigation reference, or that remounts a removed slot. All
current replacement/close callers go through the reviewed helpers, and the
persisted restoration guard checks the live dialog and live slot. No such
concrete path was found. This does not promise cancellation of an arbitrary
external async callback already executing its own delayed side effects; the
native integration uses the widget's synchronous default navigation/download
effects rather than introducing that unsupported callback behavior.

Admission, failures and write boundary

The host supplies Camp.valid for Cave and an explicit boolean RTS predicate
(:132-135). The RTS predicate calls repairWorkResidue(state)||state, constructs
HearthRTS.Camp and returns true only on success; exceptions return false. The
policy passes a clone, the repair helper itself clones, and Camp clones before
migration/reveal. This matches the destination's repair plus pre/post-migration
admission sequence without adopting the resulting camp or writing its raw source
in Cave. Adapter schema/backup row updates remain separately owned and must be
verified in the final assembled source; the host predicate cannot bypass them.

A synchronous mount/setup failure is caught by the host and replaces only the
navigation slot with an ordinary recovery status (:135). Close, Stay and Replay
are outside that slot and their handlers are already installed. Closing/reopening
can retry. Async refresh failure is handled by the widget's existing retry/status
path with generation/disposal guards. There is no catch-path fallback to a fresh
RTS camp, save adoption, automatic navigation or alternate save selection.

pagehide still calls the existing Cave save once after cleanup, and the existing
visibilitychange save remains unchanged (:153-154). Those host writes existed
before this integration. There are no added RTS/backup writes in these host files,
and persisted pageshow does not call save. Tests should distinguish widget
mount/refresh/export inactivity from the existing Cave pagehide save and the
destination loader's authorized migration/backup writes. Existing Cave
storage-conflict saveBlocked behavior is unchanged.
