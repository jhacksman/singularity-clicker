1. Loader admission: clear with the explicit host binding

Current adapter source() rejects incompatible schema rows before invoking its
validator (adapter.cjs:52–61), and browser.js:15 defaults to HearthRTS.valid.
Neither copied default suffices for the v4 destination. The plan correctly changes
the RTS compatibility row to 1/2/3/4 and explicitly supplies a clone-only check
that performs repairWorkResidue(state)||state followed by new Camp(...).

The destination really does that sequence (RTS view.js:11–20): object parse,
optional narrow legacy repair, constructor pre/postvalidation and migration,
then raw retention and adoption. The adapter already rejects null/primitive/array
payloads and passes a structured clone to validation. Camp clones again; any
repair/migration/reveal changes belong to disposable copies. Do not tick or save
that constructed camp, export its serialization, or pass it to the Cave game.
Absent RTS is handled before validation, so inspection must not create even an
in-memory fresh destination as a substitute for a rejected source.

The constructor check matters both ways: it admits recoverable historical residue
that valid() alone rejects, and rejects old inputs whose migration cannot produce
valid custody. Keep v4 negative-work repair forbidden. Native tests must include
both directional distinctions, not merely a fresh v4 save and a future v5 save.
Compare all raw slots before and after inspection and exact exports. The continued
source remains the original bytes; this eligibility check is not a repaired save,
write-permission check, committed handoff or cross-key transaction.

2. Backup recognition: proposed families match actual writers

Current RTS startup writes .before-v2 for v1, .before-v3 for v1/v2, .before-v4 for
v1/v2/v3, and .before-work-roundoff for eligible repaired v1/v2/v3. Import writes
.import-before-v3, .import-before-v4 and .import-before-work-roundoff under the
corresponding predicates. All use retainRaw's exact-byte deduplication followed
by distinct positive-numbered slots. There is no actual .import-before-v2 writer.

The proposed new families and version rows are therefore appropriate. Update
KEYS/KINDS, source-identity mapping, exact backupKind matching, browser labels,
storage-event matching and tests together. Prefix matching would be too broad;
retain complete-key and positive-suffix matching, rejecting .0, .01 and suffix
lookalikes. Enumerate unrelated key names only; never read their values.

Backup contents remain exportable even when malformed or unsupported. They must
not serve as a fallback playable camp or become completion evidence. The current
adapter preserves raw text before schema/JSON validation and browser download
preserves UTF-8 or explicitly labelled UTF-16LE code units; keep that boundary.
Assert each base and numbered backup independently rather than only a backup
count. Different whitespace must remain a distinct identity/export, not silently
normalize through the clone validator.

3. Modal lifecycle: clear with synchronous ownership and Back recovery

Current host openModal() replaces innerHTML; closeModal() closes directly, and
native cancel has a separate path (Cave view.js:128–130). The widget's WeakMap only
replaces a mount on the SAME container; replacing modal HTML creates a different
container. Synchronous host disposal before replacement/close/cancel is necessary.
Store the returned controller immediately, before awaiting controller.ready, so
closure during the initial asynchronous digest is also fenced off. The widget's
disposed/generation checks already prevent that old refresh from rendering or
initiating an action after it resumes (browser.js:77–103,138).

Keep native close cleanup idempotent and guarded by !modal.open. A close event is
queued by the HTML closing algorithm; a rapid close/reopen can therefore make an
old close notification arrive during a new opening. An unguarded callback could
dispose the new controller or clear dialogPauses behind a still-open modal.
The proposed guard must cover BOTH controller cleanup and pause/render updates.
Source: HTML Standard, close-the-dialog step 13:
https://html.spec.whatwg.org/multipage/interactive-elements.html#close-the-dialog

Root explicitly resolved the pagehide/Back question during this review: on
pageshow(persisted), reset lastNow and synchronously remount only if the modal is
still open and contains #campaign-navigation; take a fresh read and never navigate
automatically. I accept that resolution. It prevents a restored visible panel
from retaining only its permanently disposed controller/listeners, and resetting
the clock avoids treating the frozen interval as active Cave time. Closed or
replaced modals must not acquire a new widget. Retain one current controller and
the same explicit validator on this remount path.
Browser lifecycle reference:
https://developer.mozilla.org/en-US/docs/Web/API/Window/pageshow_event

Test real Back with page-transition telemetry: record whether persisted was
actually true. A normal reload on Back cannot prove the BFCache branch ran. If
headless CI does not retain that page, a separately labelled synthetic lifecycle
test may exercise the handler, but must not be called actual BFCache evidence.
Do not require cancellation of a navigation/export side effect already committed
before disposal; the essential gate is disposal during pending inspection and
protection from old callback completions mutating replacement content.

4. Native browser oracle: remove every test-side integration substitute

The existing test server injects scripts/styles into cave-integration.html
(browser test:18), then replaces the introduction and legacy link and mounts the
widget from evaluate() (:230–235). Those checks can pass while ordinary index.html
has no native integration. The plan correctly replaces them with actual built
index.html plus the real event-action/completion control.

There is a second injection seam to account for: after RTS imports, the old test
injects the widget into an extra RTS body section (:284–286) to export backups.
That can remain only as an explicitly separate helper fixture. Native backup
discovery/export evidence should return to the real Cave completion panel and
use its real controls. No addScriptTag/addStyleTag, replaced mount/container or
test-edited introduction can establish production integration.

Keep isolated helper fixtures for controlled delayed digests, failed callbacks,
same-container replacement and presentation measurements. Native lifecycle tests
should drive Stay/Replay/close/Escape/backdrop and genuine external-storage modal
replacement, hold the old read, then release it after disposal. Wait for a new
snapshot/render or actual callback completion before asserting; an old matching
status/focus predicate is not evidence that an asynchronous action finished.

Instrument writes around widget inspection, refresh and export while the Cave
modal is paused. Account separately for Cave's existing visibility/pagehide save,
Replay's intended Cave write, and the destination's migration/new-camp write.
Otherwise a blanket zero-write assertion across navigation either fails for the
wrong reason or encourages removing legitimate host persistence. A failed Cave
completion save must not be bypassed with an in-memory completion snapshot.

For destination proof, distinguish (a) no pre-navigation RTS/backup changes,
(b) successful destination migration with exact retained raw originals, and
(c) backup/main-write failure with destination recovery. Never label navigation
eligibility itself as durable migration. Fresh v4 carryMove/held fixtures should
resume paused with exact custody, but their injection remains compatibility
evidence rather than an earned Cave-to-Hearth resource transfer.

5. Host build and old-game regression boundary

The build must inline pure Cave engine, pure RTS engine, policy/browser helper
and scoped CSS before Cave view uses them. Do not include the RTS view, which
expects its own DOM and starts simulation/persistence. Preserve the other three
build outputs, existing art substitutions and legacy header routes. Expand the
unsubstituted-marker check for the new placeholder names; the current test only
matches ENGINE/VIEW/CSS/STYLES. Source-presence checks alone are not a substitute
for the native browser flow.

Current smoke.cjs:29 follows the legacy completion anchor and then exercises the
old hex Hearth's people/jobs, paused refresh, shelter, learning, maps, recovery,
migration and touch routes. The plan's split is correct: follow the new native
RTS control and prove preservation, then explicitly open supported hearth.html
for all those old tests. Keep their assertions and separate save namespaces;
deleting or skipping the old flow would turn a navigation change into lost
regression coverage. Build assertions may still retain the ordinary hearth.html
header link, but must additionally establish the intended new completion route.
