Observed integration boundaries

Host build.mjs:7-10 embeds only Cave CSS, engine and view into index.html;
src/shell.html:63 has only engine/view script slots. Native integration must
bundle the matching pure RTS engine plus adapter/browser modules before Cave
view can mount them, and include the widget's scoped stylesheet. Do not load
the RTS view: it expects its own DOM and starts a separate simulation/save loop.
Existing engine globals are distinct (CaveEngine and HearthRTS).

Host src/view.js:143 still contains the actual legacy hearth.html Continue
anchor and ember/cooking promises. Replace that completion-modal destination
slot with the widget, align the introduction to finite gathering/outpost/workshop
opening, and retain the completed-Cave facts, Stay and Replay controls. Keep
existing legacy pages available elsewhere. An absent script/validator must not
fall back to an unvalidated Continue link or a newly seeded RTS world.

The widget's browser test currently injects scripts/CSS and replaces this anchor
using page evaluation (tests/browser/campaign-navigation.cjs:18,229-235). That
proves an opt-in seam, not an already integrated production index.html. Native
acceptance must serve ordinary built index.html with no injected mount or DOM
replacement, then follow the real hearth-rts.html generated by build.mjs:21-23.

2. Modal ownership and asynchronous disposal
Keep one host-owned controller reference for the completion widget. Dispose it
synchronously before every openModal content replacement (host view.js:128),
before closeModal closes the dialog (:129), and on native dialog cancellation.
The current Escape/cancel handler (:130) bypasses closeModal; adding cleanup only
there would leave a storage listener and in-flight refresh alive. Stay, Replay,
backdrop close, close button, Settings/recovery replacement and external Cave
storage-conflict replacement (:146) all need the same idempotent disposal path.

Native dialog close should also have a cleanup fallback. Avoid letting a queued
close notification from an old opening dispose a newly opened widget; track the
current opening/controller or ignore stale close when the dialog is open again.
Mount only after the new container is attached. Keep the controller immediately,
not only after await ready, so closing during initial hashing still disposes it.

Widget browser.js:138 dispose removes click/storage listeners and invalidates
refresh generation; refresh/activate already check disposed state (:77-103).
Mounting a NEW container does not auto-dispose the OLD container's controller:
the built-in WeakMap replacement protection applies only to the same container.
Do not infer lifecycle cleanup from the modal-content innerHTML replacement.
If pagehide cleanup is added, define pageshow/BFCache remount or refresh too;
otherwise Back can restore a permanently disposed panel.

3. Exact destination-compatible validation, with no persistence
Widget browser.js:15 defaults validateRTS to HearthRTS.valid. Destination startup
instead parses the saved object, calls repairWorkResidue, then new Camp on the
repaired/original state (host src/hearth-rts/view.js:11-20). Camp performs legacy
migration and validates the resulting state again (engine.js:70).

Supply a pure explicit validation callback equivalent to:
  try { new HearthRTS.Camp(HearthRTS.repairWorkResidue(state) || state);
        return true; } catch { return false; }
The adapter already supplies a clone (adapter.cjs:61); Camp also clones. Discard
the constructed camp after checking it. Do not tick it, persist its migrated
version, retain backups, replace the actual RTS slot, or export its serialized
form from Cave. Hash/export the original raw source, including its whitespace.

This matters in both directions: valid() alone rejects recoverable historical
work residues, while an input-version validator can accept a legacy payload that
fails constructor post-migration checks. A read-only eligibility check cannot
certify quota/write access; actual destination backup/write failures remain the
destination's blocked-recovery responsibility, not a successful handoff.
