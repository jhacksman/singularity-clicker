B01 — statically closed: event observation plus replacement liveness

The corrected queued-close case at :396–412 installs a close-event observer
before the synchronous Stay/reopen fixture. The real host close listener was
registered earlier, so the observer records after that listener for the same
event. The case waits for a trusted close event, requires exactly one observed
event with modal open and two mounts, and writes its event record to an artifact.
It no longer substitutes a zero-delay timer for observing that specific event.

After event delivery and replacement ready, the test captures controller 2's
current snapshot, dispatches a labeled recognized-key StorageEvent, and requires
a different validated snapshot from that same controller. It then checks focus
remains on the expected control inside the open modal and invokes the real native
download control, comparing actual download bytes to the source.

This defeats the reported dead-but-rendered counterexample. dispose() leaves DOM
and latest intact, but removes the storage/click listeners: a disposed controller
cannot satisfy the new fresh-snapshot wait or actual export. Early unguarded
disposal would prevent ready/render; late unguarded disposal would fail the new
liveness evidence. The recorder's rendered flag describes which ordering Spark
actually observes; this review does not claim that the event was measured after
replacement render, or that every browser scheduler interleaving was exercised.

The same-turn control clicks remain explicitly synthetic. The close event itself
must be trusted/UA-generated; the subsequent StorageEvent is explicit test input,
not a claim of another-tab delivery. Actual native export is the visible liveness
result. The final report now explicitly states that completed Cave advance is
inert, so unchanged completed-camp counters do not prove the host pause flag.
